# SEO, SMM and AI discovery

Everything below is generated from `src/content.ts`. Edit the content, run
`bun run build`, and the meta tags, structured data, sitemap and `llms.txt`
all follow. There is no second place to keep in sync.

## The one thing to change before launch

`site.url` in [`src/content.ts`](src/content.ts). Canonical URLs, Open Graph
tags, the sitemap and `llms.txt` all derive from it. It currently reads
`https://kostyainc.com`.

### Why per-route HTML matters

This is a client-rendered SPA. Google executes JavaScript, so it would find
the tags eventually — but **social scrapers do not**. Facebook, LinkedIn,
Telegram, WhatsApp and X read the raw HTML response and stop. Without a real
file per route, every shared link would show the homepage's title and
description. Most AI crawlers behave the same way.

So `scripts/seo-build.ts` writes a genuine HTML file per route, each with its
own title, description, canonical, Open Graph block, Twitter card and JSON-LD.
Each also carries a `<noscript>` summary containing the same text a reader
sees, so a crawler that runs no JavaScript still gets the content.

Vercel checks the filesystem before applying the SPA rewrite in `vercel.json`,
so these files are served in preference to the fallback. That ordering is what
makes the whole thing work — do not replace the rewrite with a catch-all
redirect.

## Structured data

Published as JSON-LD on every route:

- **HomeAndConstructionBusiness + HVACBusiness** — the correct pair for a mixed
  handyman / HVAC / appliance operation. `HVACBusiness` alone would understate
  two of the three service lines.
- `areaServed` — all 14 towns in `serviceAreaTowns`, each typed as a `City`
  inside Illinois. This is the single highest-leverage field for local search.
- `hasOfferCatalog` — every service with its own URL and price floor.
- **Service** on each service page, **OfferCatalog** on `/packages`,
  **FAQPage** wherever the FAQ is actually rendered, **BreadcrumbList** on
  every inner page.

### aggregateRating is deliberately withheld

`localBusinessSchema()` emits `aggregateRating` **only** when
`googleReviews.placeId` is set. The 4.9 / 312 reviews currently on the site are
placeholders, and publishing invented review counts as structured data violates
Google's policy and risks a manual action against the domain. Wire up the real
`place_id` and the block starts emitting on its own.

## SMM

The share card is `public/og.png` — 1200×630, the size every network accepts.
`og:image:alt` is set, `twitter:card` is `summary_large_image`.

`site.twitterHandle` is empty, so the `twitter:site` tag is omitted rather than
emitted blank. Fill it in and it appears automatically.

**Before the first campaign:** the social links in `company.socials` all point
at bare `facebook.com`, `instagram.com` etc. Replace them with the real
profiles — they are also published as `sameAs` in the structured data, where
wrong values actively hurt entity matching.

Hashtag set for posts, in descending usefulness:

- Local intent: `#RollingMeadowsIL` `#ArlingtonHeights` `#PalatineIL`
  `#SchaumburgIL` `#ChicagoSuburbs` `#NorthwestSuburbs`
- Service intent: `#HVACRepair` `#FurnaceRepair` `#ACRepair`
  `#ApplianceRepair` `#Handyman` `#HomeRepair`
- Seasonal: `#FurnaceTuneUp` (Sep–Nov), `#ACTuneUp` (Apr–Jun),
  `#EmergencyHeat` (Dec–Feb)

Keep it to three to five per post, always including one town tag. Broad tags
like `#home` bring reach without leads and are not worth the slot.

## AI discovery

`llms.txt` follows the [llmstxt.org](https://llmstxt.org) format: name,
one-paragraph summary, then linked sections. Answer engines read it instead of
crawling a JavaScript app.

The **"Why Kostya Inc over other contractors"** section leads the file
deliberately — it is the part an answer engine quotes when someone asks
"who should I call for a furnace repair in Rolling Meadows". Those six points
live in `advantages` in `src/content.ts` and are the single most important
block to keep accurate.

`llms.txt` closes with an explicit accuracy note stating that company
statistics and reviews are placeholders. Remove that note once the real
numbers are in — until then it stops an answer engine repeating invented
figures as fact.

## Validation checklist

1. [Rich Results Test](https://search.google.com/test/rich-results) — paste the
   deployed URL, confirm LocalBusiness and FAQPage parse.
2. [Schema Markup Validator](https://validator.schema.org/) — no errors.
3. Facebook [Sharing Debugger](https://developers.facebook.com/tools/debug/) and
   LinkedIn [Post Inspector](https://www.linkedin.com/post-inspector/) — scrape
   each main route once so the card is cached correctly.
4. `curl -s https://<domain>/services/hvac-repair | grep '<title>'` — must show
   the service title, not the homepage title. This is the single check that
   proves per-route HTML is being served.
5. Submit `sitemap.xml` in Google Search Console; claim the Google Business
   Profile and paste its `place_id` into `content.ts`.
